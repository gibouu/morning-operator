## Current boundary

[`MediaObservationService`](../Sources/MorningApple/MediaObservationService.swift) now returns a validated [`ObservationVideoEvidence`](../Sources/MorningCore/ObservationVideoEvidence.swift) containing every requested frame before text deduplication. The store saves each acquisition and the selected ID together in the workspace. Review exposes dated and unassigned observations; Learn shows the selected uncorrected source's sample count and outcomes, and **Recognize sampled screens** explicitly calls the separate on-device [`ObservationContextClassifier`](../Sources/MorningApple/ObservationContextClassifier.swift).

[`ObservationTrace`](../Sources/MorningCore/ObservationTrace.swift) and [`ObservationTraceWindowReport`](../Sources/MorningCore/ObservationTraceWindow.swift) remain pure calculations. The evidence adapter validates classification decisions before making a trace. Learn derives a visible-context sequence from it. The new [`ObservationReviewReport`](../Sources/MorningApple/ObservationReviewReport.swift) projects the archive into individual clip moments and seven-date visual-label recurrence. It neither calls a model nor saves another report; comparable day windows and observed-use averages remain separate future integration.

    B --> C[Bounded acquisition archive and selected ID saved]

    D --> E[Validated decisions and core trace]

The importer samples at most 24 frames from a selected video up to 31 minutes and 512 MiB. It reserves a 30,000-character/256,000-byte OCR budget so rendered notes remain within 32,000 characters. Every request remains represented when text is truncated or omitted; affected frames cannot support context identification. Invalid actual presentation times retain a labeled requested-time fallback.

Optional [`ObservationOCRLine`](../Sources/MorningCore/ObservationOCRLine.swift) records add layout evidence to each frame. Each record stores a local UUID, exact line text, a `[start,end)` range measured in Swift Characters, candidate recognition confidence in `[0,1]`, and an approximate axis-aligned candidate-range box normalized to the oriented decoded image with a **lower-left origin**. It is not a device-screen tap target, exact glyph outline, semantic UI role or verified app identity. OCR confidence measures recognition, not the correctness of a context label. [Apple candidate-range bounds](https://developer.apple.com/documentation/vision/recognizedtext/boundingbox(for:)), [candidate confidence](https://developer.apple.com/documentation/vision/recognizedtext/confidence).

Core accepts at most **256 line records per frame**. Initializers and decoding validate finite positive in-range bounds, finite confidence, unique local IDs, ordered nonoverlapping ranges, and the original source scalar sequence. Visually identical but differently encoded Unicode is not an exact line span. Missing legacy layout decodes as `nil`; `[]` means no retained spans. A nonempty array can still be incomplete. No completeness or zero-geometry claim follows from absent entries.

One Vision pass preserves the existing trimmed-line order and newline joining before the usual text budgets. Unavailable, invalid or excess geometry is omitted with warnings while its text remains; no bounds are guessed or clamped. When a budget truncates OCR, only whole original line spans inside the retained prefix survive. A remaining partial text line is not given a fabricated shortened box, and source-truncated frames still cannot support identity.

The notes renderer collapses adjacent identical OCR, while structured frames retain their IDs and order. Learn and multi-observation selection now share the [source-linked proposal flow](ROUTINE-LEARNING.md), preserving independent source identities even when text matches. It uses eligible original frames or labeled corrections and discloses excluded samples. Import/retry/reimport saves evidence without inference; the person explicitly confirms missing provenance and requests a suggestion. The unified slice (`48e5c95`) passed its shared package run, native simulator build and three scoped import/provenance/negative UI journeys, without any Apple model call. Two later notice-review journeys passed after the routing changes, including review deferred until a paused morning ends; the unsigned iPhone target also builds. Initial failures and corrected reruns remain separately recorded. Context classification also uses the original structured frames. `extractText` renders the same extraction rather than running OCR a second time. Planned proposal minutes and selected-date counts are not measured duration or habit averages.

## The trace contract

Each sample has a stable ID, a relative media timestamp, an actual-presentation or requested-sampling time basis, and an outcome: observed, blank, decode failure or OCR failure. App evidence is identified with a source reference, ambiguous with a reference, or unknown. A context key is not automatically a verified bundle identifier.

The trace preserves samples in supplied chronological order. Invalid/nonfinite/out-of-range times, decreasing times, duplicate sample IDs, overlapping coverage intervals and inconsistent names for the same context key are rejected. Decoding a saved trace repeats validation. Equal timestamps are allowed: agreeing app claims form one moment; conflicting or unknown claims make that moment unresolved rather than inventing an order.

Coverage intervals mean **verified continuous captured spans**. An isolated observed frame may exist outside those spans while the surrounding duration remains unknown. Adapters must not use these intervals to mean “definitely absent media” and simultaneously supply observed frames from that absence. `nil` means continuous capture coverage is unknown; an empty array means no supported continuous span. Complete declared capture does not establish complete semantic analysis.

The adapter checks the original frame ID, exact timestamp and time basis, exact source reference and same-frame quotation. Both context validation and the trace adapter require matching UTF-8 bytes; canonical Unicode equivalence alone does not satisfy an exact citation. Duplicate decisions, foreign samples, altered times and citations from failed or truncated frames are rejected. Missing decisions remain unknown. The saved frame OCR resolves the reference; these checks do not establish that the proposed label is semantically correct or prove an action.

The classifier emits `visual-context:` identities. Without a catalog, a label must be a literal early OCR line accepted by a narrow lexical check. **Inbox → Alex → Inbox can occur within one app** and must not become an app-entry count. With a separately supplied catalog, leading punctuation/symbol decoration may be removed for comparison while the quote retains the original whole line. A second catalog mention blocks identification, including a competing name with alphabetic OCR damage; the validator does not repair such damage to establish an identity. These lexical rules constrain vocabulary and ambiguity, not OS-verified foreground identity. Optional geometry never relaxes the competing-header rule or lets the largest/highest text region establish the foreground app. The ordinary app currently supplies no catalog. Context labels, quotes and their order are never authorization to automate anything.

Classification considers at most **24 frames**. For each eligible frame it selects an unchanged, contiguous source prefix of at most **320 Swift characters and six whole nonempty lines**. An overlong line stops selection; a later convenient header cannot jump ahead of it. Deliberate excerpt selection does not mark otherwise complete source OCR as truncated. The full bounded original frame text, ID, order and times remain intact. A proposed quote must belong to both the selected excerpt and that original frame.

Selected text is capped at 9,000 characters overall, with at most four frames and 2,000 encoded prompt characters per batch. Twenty-four 320-character excerpts fit within 7,680 characters before prompt structure/catalog overhead; the separate prompt limit can reduce a batch. Blank, failed, source-truncated, empty-excerpt or over-budget frames stay unknown. The current policy is `whole-line-source-prefix-layout-v2`. Optional `inputSelection` records source character counts, selected start/end offsets, excerpt text and the local IDs of selected layout lines. Offsets use Swift characters with an exclusive end. Older saved classifications can omit all input-selection metadata or its newer line-ID field; presence records preparation, not necessarily an inference attempt.

At most six source lines wholly contained in a selected prefix supply layout hints. Prompts include their Character ranges, normalized boxes and candidate confidence; numeric hints are rounded to six decimal places while stored evidence keeps the original values. If geometry would make one frame's prompt too large, hints are removed before the text is excluded, and the saved selected IDs reflect that removal. Missing hints mean unknown geometry. This preserves the same bounded text-first input and adds no identity, action or gesture count.

Results distinguish no eligible frames, model unavailable, completed, partial failure and failure; completed inference is not proof of correct recognition. No deterministic labeler or cloud fallback substitutes for a failed or unavailable model. On the baseline's earlier text-only pure replay, the refinement selected **all 24 frames and 2,217 characters**, fixing the previous input-exclusion problem. It does not show that a model can identify those frames or resolve breadcrumb ambiguity.

## Original media timing

New native video extraction also retains each supported decoded image's original rational timestamp: integer value, timescale, epoch and flags. The existing decimal seconds remain the presentation/citation format. Missing legacy values stay absent; the app never manufactures a rational timestamp by converting saved decimals back to a chosen timescale. [Apple CMTime](https://developer.apple.com/documentation/coremedia/cmtime) describes that underlying representation.

Strict construction requires a valid nonnegative numeric time that agrees exactly with the saved decimal value. Blank, OCR-failed and text-truncated decoded frames retain their native timestamp; failed image decoding does not. Invalid optional timing encountered during restoration is omitted with a bounded warning while original text, ordinary timestamps and valid source quotations remain. Unsupported native metadata is handled separately from image decoding.

This preserves source precision for a later supported-media indexing investigation. It does **not** add presentation spans, wall-clock alignment, capture coverage or app-use duration. Rounded/nonzero-epoch fields remain inspectable metadata, not permission to use them as reliable spans. Equal rational instants and identical stored fields are separate comparisons.

## Visible visits and time

| Report value | Meaning and limitation |
|---|---|
| Minimum visible visits | Ordered appearances separated by another identified context. Includes a context already visible at the start; it is not an OS app-open count. Multiple contexts can belong to one app. |
| Minimum visible returns | Subsequent visible visits to the same context after another identified context. Unseen switches may be missing. |
| Observation duration | The declared media timeline length, not the person's entire morning. |
| Captured duration | Sum of supported continuous captured spans; unknown when those spans are not declared. |
| Sampled visible seconds estimate | Sum of adjacent, same-context sample spans within the explicit maximum-gap policy and supported captured coverage. Endpoints must use actual presentation times. This is an estimate, not measured usage, reading time or a proven lower bound on duration. |
| Unassigned captured seconds | Supported captured time that the estimate did not assign. It must not be redistributed to fill the timeline. |

There are no exact swipe, scroll, read, reply, pickup or OS app-open fields. A swipe issued by a test controller and a verified list movement belong in a separate ground-truth record. Visible message text does not prove reading; sparse frames do not reveal every gesture.

For a synthetic trace with complete coverage from 0 to 10 seconds and a two-second gap limit:

| Media seconds | 0 | 2 | 4 | 6 | 8 | 10 |
|---|---|---|---|---|---|---|
| Identified context | A | A | B | B | A | A |

The report preserves **A → B → A**: A has two minimum visible visits and one return; B has one visit. Same-context spans contribute an estimated four seconds for A and two for B. Four captured seconds remain unassigned at context changes. Actual app-use time and exact app openings remain unknown.

Repeated identical A samples do not create another visit. **A → unknown → A** supports only one minimum visit and no duration across the unknown moment. First/last sample times on a visit describe observations, not a claim of uninterrupted use. A maximum-gap rule is an explicit assumption; it cannot rule out shorter unseen switches.

## Source-linked clip and period review

[`ObservationClipReview`](../Sources/MorningApple/ObservationReviewReport.swift) reads one acquisition's original frames and attached validated classification. The [clip view](../Sources/MorningOperator/ObservationReviewViews.swift) presents proposed visual labels, ambiguous or unknown moments, and their original sample IDs, outcomes, relative times and exact source quotations. Requested-time fallback remains labeled. A literal label such as **Today** stays a visual label; it does not become Calendar, a verified app identity or an action.

Equal effective timestamps form one moment while preserving every source request. Matching claims can agree; conflicting identities or a known claim tied with an unknown sample remain unresolved. Unknowns remain in the displayed sequence, and **A → unknown → A** does not fabricate a return. Visits and returns come only from the existing conservative trace within that one clip. If actual frame times decrease, that clip retains its samples in extraction order with unknown contexts and no visit report; it does not suppress the other valid clips in the period. The UI explains that its chronology is unresolved.

[`ObservationReviewPeriod`](../Sources/MorningApple/ObservationReviewReport.swift) uses seven Gregorian local date labels ending on the selected date, including daylight-saving boundaries. It matches each acquisition's saved local day, then partitions by the **exact saved time-zone identifier and origin**. Human, synthetic, automated and unknown-origin records remain separately browseable; only human partitions belong to personal summaries. Undated observations remain outside the period until explicitly dated. Import time, filenames and media offsets never supply that date. Separate clips on a date are not concatenated into a timeline or assumed to have a known order.

The [period view](../Sources/MorningOperator/ObservationPeriodReviewView.swift), reached from Review's **From your observations**, reports each literal context as **seen on N of D days with labeled samples**. N counts distinct saved dates with that exact context; repeated samples or several clips on the same date contribute only one day. D counts dates in that same zone/origin partition with at least one resolved labeled moment. It is not seven by default and is not a denominator of complete mornings. The report separately exposes observed dates, dates without observations, observed dates without a label, corrected dates and dates containing unresolved moments. A day with some labels can still contain unknowns.

Every appearance links back to acquisition/sample IDs and the accepted same-frame quote. Exact context key and label bytes define identity; conflicting labels for one key are omitted from recurrence while the original clips remain inspectable. There is no semantic grouping of similar labels into an app or habit. Correction, redating, origin changes and deletion take effect by deriving the report again from current source records; relaunch creates the same projection from the saved archive. No extra text copy, report cache or inferred date is persisted.

All ordinary clip reports still pass `capturedIntervals: nil`. Known media length does not establish continuous capture coverage, sampled duration, total app usage or time saved. This view adds no duration averages, swipe/read/reply/pickup counts, cross-clip visit sums or model-accuracy claim. Its recurrence is separate from the stricter comparable-window calculation below.

The focused [`ObservationReviewReportTests`](../Tests/MorningAppleTests/ObservationReviewReportTests.swift) run passed **13/13 synthetic shared tests in 0.009 seconds**, with no skips. These cover exact source links, unknown/ambiguous/tied moments, decreasing actual timestamps, repeated clips and distinct-date counts, zone/origin isolation, correction/redate/delete/reload recomputation, conflicting labels, invalid quotations and daylight-saving date ranges. The first compile attempt failed on a collection predicate call; the corrected rerun passed. No model, OCR or native UI was exercised by these tests. Both new native simulator review journeys now pass across scoped runs, alongside two compact-home regressions; final simulator and unsigned iPhone builds pass. The [verification record](PHASE-ONE.md) preserves exact timing, earlier failed UI assumptions and an interrupted diagnostic-finalization phase. None of these synthetic checks validates actual model labels; the earlier benchmark outcomes above remain historical evidence.

## Four usable days in a five-day window

`ObservationTraceDay` explicitly assigns a trace to a date, time zone and comparison key. Relative movie timestamps do not supply that calendar date. `ObservationComparisonPolicy` declares the expected window length, allowed duration difference and maximum sample gap.

The app can now retain multiple acquisitions and their frame evidence, keep unknown dates unassigned, and group explicitly dated records in Review. This is an acquisition archive, not a set of verified complete mornings. It does not yet feed those records into `ObservationTraceWindowReport` or display observation-derived app-time or habit averages. Four records can be four partial clips from one day; record count is not a count of independent comparable mornings.

A comparable window must have the selected origin, matching comparison key, complete declared capture, duration within policy, at least two distinct moments, resolved context identities, actual presentation times and sample gaps within policy, including the edges. Incompatible or partial days are excluded with a reason; absent days are listed separately. Unknown origin is excluded. A different time-zone identifier, duplicate day or reuse of one trace ID on multiple scheduled days is rejected rather than silently combined.

Human and synthetic comparisons are separate: `.human` is the pure comparator's default origin, and an explicitly synthetic report excludes human records. Archive origins independently distinguish human, synthetic, automated and unknown; a date assignment does not silently turn an unknown or automated clip into a human example. Any future adapter must preserve these distinctions and require supported coverage. A synthetic report is not personal morning history.

For arithmetic illustration, visible-visit lower bounds `[2, 3, 1, 2, unknown]` yield a mean of **2 over 4 evidence days**, with a range of 1–3 and one day without evidence. The denominator is not five. This is an example, not a measured benchmark result.

Each metric has its own denominator. A day may support a visible visit but no same-context duration span, so the duration mean can use fewer days. An app absent from all identified moments of an eligible window contributes zero to its **minimum visible-visit count**; that does not assert zero actual app use between samples. An unavailable duration remains unknown. No usable days produce no app metrics and an unknown mean. Means of visit lower bounds remain lower bounds, and sampled-time means remain estimates.

## Acquisitions, corrections and retention

[`ObservationArchive`](../Sources/MorningApple/ObservationArchive.swift) keeps immutable acquisition IDs, source kind/label, original text, optional structured video evidence, optional local file SHA-256 identity, origin, dates and any attached context result. `importedAt` is separate from the optional observed date. New imports have an import time; migrated latest-only data has no invented import time, observed day, fingerprint or origin. A native recording keeps the explicit recording-output start callback's session ID/date/zone in a separate immutable `recordingContext`. It initially supplies the observed day, but changing or removing that editable day never changes the original context. Legacy missing context remains unknown even if an older observed day says recording-session provenance. It does not establish exact first-pixel time or complete coverage. Other recordings remain in **Date needed** until the person assigns a day and original time zone. Filenames, media PTS and import time never supply an observed day.

A local fingerprint is streamed from the selected file; the importer checks it before and after extraction. Reimporting the same digest selects the existing acquisition and preserves its original source, corrections, date, import time, origin and ID. Reclassification updates that acquisition instead of creating another record. Without a fingerprint, a stable acquisition-ID retry can deduplicate; equal OCR text alone does not merge independent records. Legacy files without fingerprints cannot retroactively prove same-file identity. An owned recovery retry can fill missing native recording context on an exact-digest match, without replacing an existing context or changing the chosen day, origin, corrections or classification. The workspace must save before recovery cleanup.

Corrections are separate from original text. Their presence removes attached classification and hides the original video's interpretation from the corrected Learn notes, while original text, frames and layout remain reviewable in the saved observation. Returning to the original text does not resurrect a removed interpretation; it can be requested again. Header excerpts never replace source OCR. Selection, date/origin changes, deletion and notes use explicit/lifecycle persistence boundaries. The archive and selected ID are saved in the same workspace write; mutation failure reports the error instead of silently evicting older acquisitions.

The archive rejects additions beyond **60 entries**, **8 MiB of aggregate source/correction/frame/line/excerpt text**, **20,000 retained OCR line records**, or **16 MiB of compact archive encoding**. The complete pretty-printed workspace can be larger because it also holds routine state and selected aliases. Each original is capped at 33,000 characters, including a bounded existing recording-coverage prefix; each correction is capped at 32,000, and each is limited to 300,000 UTF-8 bytes. Existing per-video frame/text limits still apply. There is no automatic age-based deletion or eviction.

Classification installation checks cancellation, the selected acquisition ID, the evidence ID and source citations. Archive restoration also validates derived status/counts and prepared-input provenance. Malformed, oversized or unsupported derived classification is removed with a fixed warning while valid original evidence and notes remain. Invalid source text, layout and ordinary timestamps are not silently repaired. Malformed optional recording-start metadata is omitted with its own fixed warning, leaving valid originals and the assigned date intact. A damaged pending recovery sidecar instead blocks import and deletion: its movie and metadata are the only remaining source and stay available for repair/retry or explicit discard. Derived reports are recomputed; no measured-use summary is invented. No frame pixels are stored by this path.

**Clear observation** removes the selected acquisition and its current aliases. **Delete this observation** leaves other acquisitions intact; **Delete all observations** removes the archive and current aliases. These controls do not delete routine/history quotations, notes saved through the separate capture feature, original imported files, or an independently pending raw recovery recording. A pending raw recording has its own Discard action. The selected record's original evidence is retained through ordinary corrections until that record is explicitly deleted.

All-blank or failed-sample video extraction returns structured diagnostics to its caller. When no readable text exists, the store **preserves the previous notes, frame evidence and classification**, reports the sample-count failure, skips routine proposal and keeps an owned raw recording for retry/discard. It does not save the blank import over the previous observation. The text-only convenience API still throws when there is no recognized text. An owned raw clip is also retained after extraction, cancellation or persistence failure; only a successful workspace save containing its acquisition and selected ID permits removal. Later classifier/model failure does not restore deleted raw video. User-selected originals are not deleted. Saved routine quotations can outlive clearing the latest observation. See [architecture and retention](ARCHITECTURE.md).

The app passes no trusted continuous-capture intervals when deriving a selected observation's report, so capture duration and sampled-time estimates stay unknown even when media duration is known. A benchmark may separately declare verified host-capture intervals; controller actions are not evidence of capture coverage. If replay is needed, retain the synthetic benchmark original explicitly. There is no hidden raw recording archive.

## Controlled benchmark and remaining checks

The first native driver, movie and import/persistence checks are complete; inference accuracy, held-out cases and independent multi-day sessions remain open. The earlier Mac model attempt was unavailable with zero requests. The later simulator attempt reached recognition and reported availability, but **all six requests failed, no responses returned, and all 24 decisions stayed unknown**. Its app-process native log reported `operationNotAllowed: Simulator is not supported` in a required backend. This establishes a runtime support failure; it is neither a content-violation finding nor measured model abstention. A follow-up diagnostic UI check also failed with the same six-request/zero-response/24-unknown result. Its six sanitized native-error categories are `other`; they contain no error descriptions. The unsupported-simulator cause comes from the separate local app-process log, not from that sanitized category. No physical-device context-model benchmark has run. The complete protocol is:

1. Build two test-only native fixture apps from one small source: a scrollable synthetic inbox and calendar, with stable row identifiers and no accounts or external writes. One app with two screens can test scene changes but cannot prove cross-app entries.
2. Drive a bounded A → B → A sequence (the first run used 45 seconds of deliberate holds and took 91.870 seconds including navigation) with bounded XCTest actions and visible postconditions. Log attempted swipes separately from demonstrated row movement, and foreground activation separately from a new entry. Keep timestamps and capture-alignment uncertainty. Use actual simulator video, then finalize it before import.
3. Send only that movie through the real extraction, structured adapter and report. Verify saved evidence is visible and survives relaunch. Pass the same saved OCR to the existing routine proposer independently. Model unavailability, guard abstention, model abstention and inference failure are distinct outcomes. Never feed controller truth or expected counts into classification. Text fixtures cannot substitute for a failed movie.
4. Compare claims with the controller's separate truth, matching only equivalent metrics one-to-one. Report false positives, misses, comparable count errors, timing bounds, unknowns and both capture and sampling gaps. Show all scripted events as well as those visible in analyzed samples; scoring only visible events would hide sampling misses.
5. Hold out a reordered sequence with different synthetic text. Include a rapid visit, static screen, repeated content, no-movement swipe, ambiguous/blank frame and setup-only versus mixed activity. Injected extraction failures are fault tests, not observed OS failures. Then run four or five independent comparable synthetic windows to verify day denominators; copying one clip to several dates is not several mornings.

Choose scoring definitions and thresholds before the held-out run. Simulator video validates that development path, not the phone's ScreenCaptureKit lifecycle. The later phone trial requires the owner's explicit system approval, an unobscured fixture sequence, the ordinary finalized-recording/import flow and separate confirmation of visible evidence and model output. A pass must not be generalized to arbitrary apps, protected content, long captures, pickups or personal habit accuracy.

Raw movies, OCR, controller logs and result bundles stay local and ignored. Publish only reviewed aggregate results with source revision, scenario version, device/OS, model availability and a proceed/fix/stop decision.
