## First setup and morning

1. Open **Learn → 1 · See your rhythm → Connect Screen Time**. Authorize deliberately, inspect the dates/coverage returned and review the proposal's estimated order and minutes. Empty, denied and failed are different outcomes. Screen Time does not reveal every tap, message or scroll.
2. Optionally record/import one or more observations. Review extracted text, original samples, observed date, time zone and personal/test origin. Unknown dates stay unknown until corrected. Select saved video observations, browser lessons and returned dated Screen Time aggregates to build one sourced suggestion. Unknown coverage remains visible; the compatible direct Screen Time suggestion also remains available. Adjusting a suggestion opens an unapproved draft; no source approves itself.
3. Review and edit the routine's moments, order, supported destinations and budgets. **Let MORE take care of my morning** saves the reviewed operations and plan. One routine is reused each day; later edits produce a draft requiring approval. A running/paused morning keeps its approved version.
4. Open a website during learning or let an approved routine open it directly. When the service asks for sign-in, connect on its visible page inside MORE; there is no mandatory connections checklist. The existing persistent WebKit store retains the session until the provider expires/revokes it or you clear website data. During execution, sign-in pauses the saved budget and supported content readiness resumes the same moment. **Settings → Apps & accounts** remains optional access management. “Ready” there is your confirmation, not an automatic credential check. LinkedIn and Slack use this browser path independently of the optional API catalogue; real provider/account acceptance remains [#251](https://github.com/gibouu/morning-operator/issues/251).
5. In **Settings → Apps & accounts → Read Gmail in MORE**, complete Google's consent. Read access and optional read/send access remain explicit choices. The same saved native connection serves the reader and Gmail routine moments. A routine moment can prepare/revise a source-bound reply or a message to the connected account itself, review it fully, then send after a separate instruction. Composio's additional Gmail actions use a different connection. Saved native access and bounded Inbox reading are physically verified; the authorized acoustic send is still pending. See [Gmail reading](GMAIL-READING.md).
6. In Settings, open **Calendar & weather** to configure **Your day** for selected calendars and an optional city. A Google calendar synced into iOS Calendar can use EventKit. The direct **Apps & accounts → Google Calendar** route now lets you choose a named calendar for a current-day reading; its dates and phone time zone are recalculated at execution. **Calendly** offers the same review path for appointments that start today. Both disclose bounded partial readings, keep Repeat local and require explicit refresh. **Outlook** now offers up to three unread Inbox previews for a named mailbox and an explicit choice to read one observed message; Repeat stays local and Refresh obtains new previews. Its native synthetic journey passes, while a real account and replies remain unproved. See [Outlook reading](OUTLOOK-INBOX.md). Other generic saved actions still reuse fixed query values. See [Google Calendar](GOOGLE-CALENDAR-DAY.md) and [Calendly](CALENDLY-DAY.md). Choose one route per calendar to avoid duplicates. The direct **Settings → Health** entry offers optional, read-only sleep, heart-rate variability (SDNN), resting heart rate and respiratory rate from Apple Health. They start off; an existing sleep-only connection needs an explicit upgrade for the additional types. Current values show their recorded source and time, with longer details collapsed. A tracker must actually write the supported data to Apple Health; MORE does not invent a proprietary recovery score. Empty data never proves a refused permission. See [Health setup and limits](YOUR-DAY.md#sleep-duration); actual source coverage needs its own device acceptance. Current weather is not a full-day forecast.
7. Return **Home → touch the landscape → Play** with an approved routine. Play starts its first step directly on Home, with no listening preparation, opening choice or online-voice consent sheet. Pause and Play control the same session. Prepare optional listening from Settings or onboarding; unavailable listening never blocks execution. Apple local speech remains the default; online conversation stays an explicit Settings choice. Without a routine, Play opens preparation; a draft opens review before it can start. Revealing controls alone never starts playback.
8. Choose the operation for each browser moment before approval; existing web plans remain manual until edited. Automated moments browse at the saved pace and can continue when the allotted budget ends; an uncertain effect stops for reconciliation. Personal timed moments continue after their budget; actual spoken operations continue after completion. See [routine execution](ROUTINE-AUTOMATION.md). Use MORE normally. Supported speech can finish its own operation; unconnected external activities wait for the owner. A supported app handoff keeps one saved timer. +2/Next, lock/background/return and actual external targets require their own phone acceptance. Ordinary narration pauses when MORE backgrounds; a target timer can continue. Timer expiry does not prove a lesson ended or force another app forward.
9. Finish and inspect the recap. Optional reflection is reviewed before Save; opening an invitation does not start the microphone. Planned time, routine elapsed time and observed app use are different measures.

## Recording, privacy and models

Native capture offers 5, 10, 20 or 30 minutes with a monitored 256 MiB stop. The periodic monitor is not an exact hard byte ceiling. Selected-video import is at most 31 minutes/512 MiB and samples up to 24 frames. Long text analysis does not mean continuous video coverage or measured scrolling speed. Review what the app actually retained.

Open **Settings → Privacy & data** to inspect retained categories and the full local Forget control. Confirming Forget removes app-owned state/copies and the saved Gmail credential; incomplete cleanup blocks ordinary work and can be retried. Originals in Photos/Files, exported files, Apple-app items, account grants and backups remain separately managed. Do not reset the owner's data to perform a test. [Exact privacy scope](PRIVACY.md).

**Settings → Talk with MORE → Use ElevenLabs** offers an explicitly chosen online conversation even without an active morning or saved routine. The consent screen explains microphone and MORE’s readings, including explicitly requested previews, sharing before connection; Apple Health permissions alone do not enable cloud sharing. A new morning closes an existing conversation and needs its own choice; effect tools stay unavailable outside an active morning. Closing the conversation or leaving the foreground stops it. The default remains local speech. See [natural voice and verification limits](NATURAL-VOICE.md).

Current inference uses Apple's on-device model when available. Check its availability message; hardware, language, region, settings and model readiness matter. Unavailable inference is not an empty result. An optional iOS 27 beta PCC route needs separate entitlement, explicit selected cloud inputs and real-device evaluation before it can be enabled. [Model plan](APPLE-MODEL-PLAN.md).

## Set up a development Mac

Clone the repository with your own GitHub access. Never put tokens in repository URLs or files.

```sh
git clone https://github.com/gibouu/morning-operator.git
cd morning-operator
git switch main
./scripts/check-environment.sh
./scripts/test.sh
open MorningOperator.xcodeproj
```

Use full Xcode compatible with the phone and the guarded APIs being built; the observed setup used Xcode 27 and iOS 27.0.1. Select Xcode's command-line tools and finish first-launch setup. Deployment targets do not prove every older OS/hardware combination. The environment script exits 2 if full Xcode is unavailable; package checks are a separate result.

Choose the **MorningOperator** scheme, paired/unlocked phone and your signing team for the app and embedded **MorningActivityWidget**. Resolve required WeatherKit/Screen Time provisioning for the intended features. Do not commit team/device settings, signing profiles or credentials. XcodeGen is needed for project regeneration/device-test tooling, not for opening the checked-in project. Review generated diffs after changing `project.yml`.

The repository's Google defaults are inert. Each developer configures a matching iOS OAuth client/callback locally; there is no iOS client secret. Canonical configuration locations and override names are in `AGENTS.md`. This developer setup is not the end user's path: users connect Gmail in MORE on their iPhone.
