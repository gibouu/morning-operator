# Natural conversation in MORE

16 October 2026 · [Voice #116](https://github.com/gibouu/morning-operator/issues/116), [voice choice #20](https://github.com/gibouu/morning-operator/issues/20).

## Choice and data flow

**Settings → Voice** offers only **Male / Female** (**Homme / Femme**) and a fixed example to listen to. The preference persists across launches and language changes. The example uses ElevenLabs without opening a microphone or sending routine content. Other app-owned sample buttons use the same path. Provider names belong in the privacy disclosure, never in a provider selector.

ElevenLabs is the primary synthesis route after agreement to share the selected narration text for the current morning. Declining keeps Apple speech for that morning without repeatedly presenting the same choice. This text-only route opens no microphone or conversation. A real provider or playback failure releases remote audio before the same pending narration continues through Apple; it never replays a tool or advances an unfinished reading. Stop, cancellation, language/gender changes and privacy invalidation cancel pending work instead of triggering a fallback. Apple prefers the selected language and known gender, then Premium over Enhanced over Standard among installed voices. If that combination is absent, the policy can use the best available language voice; it cannot guarantee a downloaded Premium voice or an audible gender without inspecting the phone's installed inventory.

**Settings → Talk with MORE → Talk** starts the explicitly disclosed online conversation, with or without an active morning or saved routine. Its disclosure explains that microphone audio, selected narration text and requested previews or recaps go to ElevenLabs and its Google Gemini model. This can include chosen Health, calendar and message content; Apple permissions alone do not enable that sharing. Raw recordings, complete Health history and unread account contents are not automatically submitted. An active morning's pinned routine steps remain available in the disclosure. The on-device listener and speech release ownership before the SDK takes the microphone. The current agent uses Gemini 3.5 Flash with Eleven v4 Turbo; authenticated settings have Zero Retention Mode enabled, recording disabled and LLM cascading disabled. These are verified provider settings, not an independent audit of every system log or subprocessor.

The long-lived provider key and private agent ID stay in the backend. The app authenticates with its existing installation token and receives only a temporary WebRTC conversation token. Starting this mode does not subscribe to a provider plan or purchase the MORE subscription. The private prototype restricts token issuance to explicitly activated installations; a new phone's first request can require administrative activation.

## Provider configuration contract

The ordinary text-to-speech path is `POST /v1/voice/speech`, authenticated by the same installation bearer and private activation allowlist as `/v1/voice/token`. It accepts exactly `text` (nonempty, at most 32,768 UTF-8 bytes), `language` (`fr` or `en`) and `voiceGender` (`male` or `female`). The server fixes the public premade voice: Roger (`CwhRBWXzGAHq8TQ4Fs17`) for male and Sarah (`EXAVITQu4vr4xnSDxMaL`) for female. The provider's authenticated metadata lists both French and English for these voices; no native French voice was available in this account's French-filtered collection. No voice is created or cloned.

Standalone synthesis uses `eleven_turbo_v2_5`, with an explicit `language_code`, `output_format=mp3_44100_128` and `enable_logging=false`. Refusal of that logging setting fails closed; there is no retry with logging enabled. The provider accepted four bounded synthetic FR/EN × male/female requests with these exact settings. This establishes accepted requests and returned audio, not a separate audit of supplier retention. The backend allows at most 20 seconds and 8 MiB of MPEG audio, rejects redirects and malformed responses, and returns sanitized failures. Neither selected text nor returned audio enters D1, the business execution journal or application logs. An explicit repeat synthesizes again; it does not invoke a business tool.

The explicit conversation keeps its existing Gemini 3.5 Flash / Eleven v4 Turbo model, prompt and three client tools. SDK 3.4.0 sets only `AgentOverrides.language` and `TTSOverrides(voiceId:)` using the same two public voices. The private agent permits only those language/voice overrides; prompt, model, tool and knowledge-base overrides remain disabled. The provider configuration update changed only `platform_settings.overrides.conversation_config_override.tts.voice_id`; a before/after comparison confirmed all other conversation, platform, workflow and name settings identical. Long-lived API keys and the private agent identity remain server-side.

Provider references: [TTS parameters and logging](https://elevenlabs.io/docs/api-reference/text-to-speech/convert), [voice metadata](https://elevenlabs.io/docs/api-reference/voices/search), [allowed conversation overrides](https://elevenlabs.io/docs/eleven-agents/customization/personalization/overrides).

## Conversation and execution

The official Swift SDK 3.4.0 owns continuous audio, streamed responses and interruptions.

Home and the conversation screen show the person’s words as they are recognized, in the same caption area as MORE’s response. Long input keeps the newest short passage visible; corrections replace the current hypothesis without accumulating a history. Local morning speech uses its existing partial results. In online conversation, an on-device recognizer observes the SDK’s existing microphone track for display only, without taking another audio session or sending audio to Apple. Speech permission and local recognition support are required for this live preview; otherwise the final provider transcript remains available. Provisional captions never authorize actions or write personal memory; only the existing final transcript path can do so.

One conversation retains context across turns. Routine metadata is updated when the current moment changes. Source text enters through an approved narration message, with a fresh narration ID; it is data, never an instruction to perform an action.

The model has three client tools, with no provider action tools:

- `more_control`: one bounded pause, resume, next, skip, stop or extension, bound to the current session and step and a real microphone event.
- `more_request`: the exact latest microphone transcript, passed to MORE's existing source-bound service dialogues. The app accepts or refuses it; an accepted/pending response does not confirm sending anything. Existing draft review, send instructions, account checks and uncertain-effect reconciliation remain authoritative.
- `more_narration_complete`: the current narration ID, requested after speech. The app also waits for the SDK's remote speaking state to end. Interruption, stop, replacement or a deadline throws instead of advancing a routine on incomplete speech.

Only one effect is accepted for a microphone event, even if the model emits multiple tool-call IDs. Service requests do not receive arbitrary backend tools or credentials. Pending requests suppress voice and captions until an app narration or a new actual microphone turn authorizes output again.

Final microphone transcripts also reach MORE's existing personal-fact extractor, including outside a morning. It uses the already selected Apple model or the separately enabled OpenAI route; unavailable extraction leaves memory unchanged. Agent replies, approved narrations and service text never enter this learning callback. The raw saved-fact store is not added to Gemini's context; relevant facts can appear in the app's consented narrated answer. An app-delegated contextual answer uses the selected model and existing memory once, then follows the consented narration route; general OpenAI context excludes both sleep and other Health measurements. A new microphone turn, model choice, language, session or privacy generation rejects an outdated answer or pending memory update.

## Lifecycle

Consent is memory-only and bound to the current session identity, pinned routine, language and privacy generation. Without an active morning, conversation and requested narrations remain available but effect tools are refused. Creating a new morning identity closes the existing conversation before its context can be uploaded; sharing does not transfer automatically to a new morning. Leaving the foreground, ending the morning, changing language or gender, withdrawing Health, losing subscription access or forgetting local data stops pending online work. A provider failure may deliberately switch the pending narration to Apple only after asynchronous SDK/audio release. That release preserves the original narration completion gate; it does not replay a caption, routine action or service request. A manual dictation turn also waits for release before taking the microphone. Changing the synthesis route never silently changes the selected inference model.

The SDK's interruption method has no public cancellation acknowledgement or rendered-audio drain signal. Its speaking state uses LiveKit audio activity. A narration marker plus that state is stronger than a model-text callback, but actual audio cutoff and completion still need iPhone acceptance. LiveKit logging is disabled; ElevenLabs uses error-only logging with debug mode off. Its SDK has no public logging-off option, so do not claim an absolute absence of sensitive OS logs.

## Evidence and remaining checks

Live user captions (16 October 2026): **84 shared Swift tests in seven suites passed**, including provisional/final isolation, corrections, bounded input, stop/stale callbacks and current voice fallback/briefing compatibility. **Four iOS simulator UI tests passed**: progressive words and correction, long French input at the largest text size in night mode, automatic passage progression, and actual local speech output replacing the passage. The input UI checks inject presentation-only hypotheses; they do not exercise a microphone or a provider. App, widget and UI-test targets compile for the simulator. [Physical microphone and online-track acceptance remains #216](https://github.com/gibouu/morning-operator/issues/216); acoustic latency, echo and live PCM delivery are unverified on an iPhone.

- Gender/TTS backend, 16 October: **51 Node/Workerd tests passed**. The deployed endpoint returned `200 audio/mpeg` for all four synthetic French/English × male/female requests with `no-store`; unauthenticated, inactive and malformed requests retained their rejection gates. The production catalog, database, business journal and existing activation remained unchanged. The owner phone was not activated by these synthetic checks.
- Direct provider checks accepted the same four bounded synthetic requests with logging disabled; two SDK conversation checks confirmed the voice override without opening a phone microphone. These prove accepted requests and returned audio, not audible iPhone playback or personal Health sharing.

- Model/memory compatibility selection: **65 tests in five shared suites passed**, covering final microphone provenance, duplicate extraction, stale-turn narration, invalidated memory admission and exclusion of both sleep and other Health segments from general OpenAI context. Injected models/transports only; no provider call or microphone in this selection.
- Shared lifecycle/output checks: 17 tests passed, including pending-output suppression, explicit reopening, duplicate-event protection and cancellation. Synthetic transports only; no microphone or provider call in those tests.
- Real provider French test: private connection and clean close; 37 PCM chunks, about 14.7 seconds of synthetic audio. First audio arrived in 1.10 seconds; an approved narration and all three client tools were observed with synthetic IDs and no app effects.
- Real provider English test: private connection and clean close; eight PCM chunks. First audio arrived in 0.96 seconds. No subscription change or blocking quota was encountered during these bounded checks.
- The provider test exposed an ambiguous spoken acknowledgement after an accepted/pending request. The client now closes audio and captions during that phase; this is a client regression check, separate from the supplier's model behavior.

These results establish real provider connectivity and generated audio, not microphone recognition, iOS LiveKit playback, route changes, audible interruption or real provider effects on a phone. Keep all tokens, session identifiers, audio evidence and raw logs private.
