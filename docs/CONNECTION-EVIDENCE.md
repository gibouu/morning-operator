## Gmail configuration and owner proof

The normal setup location is the existing website-connections screen. Its Gmail section is a native API reader; the remaining website queue keeps its existing behavior. A saved in-app Gmail URL moment opens the same reader without loading Gmail in WebKit. A native **Open Mail** moment remains an attempted `message://` app handoff; iOS inbox navigation is unverified and is never treated as API access. Gmail is not automatically inserted into the opening speech or connected to a background collector.

For a developer who already has an authorized Google project/client:

1. Check the Google client is type **iOS** and its bundle identifier matches this app's signed bundle ID. Check Gmail API enablement, consent/test-user eligibility and the `gmail.metadata` scope. No remote setup was changed by this PR.
2. Set the local Xcode build values `MORE_GOOGLE_CLIENT_ID` and `MORE_GOOGLE_CALLBACK_SCHEME`. The callback is the reversed client ID: `123-example.apps.googleusercontent.com` becomes `com.googleusercontent.apps.123-example`. Use local build overrides or an ignored `work/Gmail.xcconfig` passed with `xcodebuild -xcconfig`; do not commit account configuration, credentials, tokens or signing data. The app validates exact scheme registration before opening consent.
3. In the ordinary signed app, choose **Connect Gmail**. The system authentication browser asks for Google's normal consent. Cancel/deny must leave no count. Account policy or test-user restrictions can still block consent.
4. Compare the returned Inbox **message** count against the same Google account, including a verified zero if available. Record only outcome and build ID; keep account content and screenshots out of Git. Test Refresh, denied/revoked access, network failure and expiry separately.
5. Leaving this screen or backgrounding MORE drops the local access session/count. This bounded implementation does not persist credentials, request offline access or refresh tokens. Google may still return a refresh token for an installed app; it is discarded. Google retains its separate account grant until the owner manages it in Google Account. No remote revocation was performed.

The API surface is `GmailOAuthConfiguration` → `GmailAuthorizationRequest` → `GmailConnectionService.completeAuthorization` → `inboxUnreadCount`. `GmailInboxSnapshot.isCurrent(at:)` expires at 60 seconds; stale counts are hidden pending Refresh. Only a successful, valid INBOX response can establish zero. HTTP failures, redirects, malformed data, missing scope and expired access never become zero. The default transport has no persistent cache/cookies/credential store, refuses redirects and bounds request time. The session and authorization-attempt debug descriptions redact credentials.
